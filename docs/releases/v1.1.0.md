# v1.1.0 — İmza düzeltmesi, toplu doğrulama ve token önbelleği

**Yayın tarihi:** 25 Ekim 2026
**Hedef servis:** TumKutukDogrulaServis 2025/08/01 (`http://kps.nvi.gov.tr/2025/08/01`)

```bash
npm install @yucelozalp/kps-identity-client@1.1.0
```

## Öne çıkanlar

- **"An error occurred when verifying security for the message" hatası çözüldü (#1).** 1.0.x sürümlerinde KPS servisi her sorguyu bu hatayla reddediyordu.
- **Yanıtlar artık doğru okunuyor.** 1.0.x, KPS 2025/08/01 yanıt yapısını yanlış okuduğu için her kişiyi "Kayıt bulunamadı" olarak döndürüyordu.
- **Daha hızlı.** STS token'ı önbelleğe alınıyor, her doğrulama iki yerine tek istekle yapılıyor. Yeni `verifyMany()` ile N kişi tek sorguda doğrulanıyor.
- **KPS 2025/08/01'in yeni alanları:** TC Kimlik Kartı seri numarası (`TCKKSeriNo`), Mavi Kart sahipleri için `Ulke` ve KPS hata bilgisi (`HataBilgisi`).

## Düzeltilen hatalar

### İmza doğrulama hatası (InvalidSecurity)
İstek imzalanırken digest ve HMAC, `Timestamp` ve `SignedInfo` elemanlarının boşlukları silinmiş bir kopyası üzerinden hesaplanıyordu. Zarfa ise girintili ve `<x/>` biçiminde kopyalar konuyordu. KPS (WCF), gelen elemanları Exclusive XML Canonicalization ile yeniden oluşturup doğruladığı için değerler hiç tutmuyordu. Artık bu iki eleman doğrudan canonical biçimde üretiliyor; imzalanan baytlar ile gönderilen baytlar birebir aynı.

Düzeltme, gerçek servisin yaptığı doğrulamayı taklit eden testlerle güvence altına alındı: test sunucusu her isteğin imzasını Exclusive C14N ile kontrol ediyor. Aynı doğrulayıcı 1.0.1'in ürettiği isteği "Timestamp digest mismatch" ile reddediyor.

### Yanıt ayrıştırma
KPS sonuçları `SorgulaResult > SorguSonucu > TumKutukDogrulamaBilgileri` altında döndürüyor. 1.0.x ise sonuçları `SorgulaResult > DoluBilesenler` altında arıyordu. Bu yüzden servis kişiyi bulsa bile sonuç `status: false, code: 2` ("Kayıt bulunamadı") oluyordu.

### Türkçe büyük harf
İsimler `toUpperCase()` yerine Türkçe kurallarla büyütülüyor: `ali` → `ALİ`, `ışık` → `IŞIK`. Önceden `ali` → `ALI` oluyordu ve NVİ kaydıyla eşleşmiyordu. Fazladan boşluklar da tek boşluğa indiriliyor.

### Diğer
- STS yanıtı önek (namespace prefix) bağımsız okunuyor; assertion ID, `SAMLAssertionID` tipindeki `KeyIdentifier`'dan alınıyor.
- Ayrıştırma hataları artık iç içe sarılmıyor, asıl neden mesajda kalıyor.
- Geliştirme ortamı onarıldı: kilit dosyası yüzünden testler hiç çalışmıyordu (`Cannot find module 'jest-util'`), ESLint 9 da yapılandırma bulamıyordu.

## Yeni özellikler

### Toplu doğrulama: `verifyMany()`
```typescript
const results = await client.verifyMany(
  [
    { tcno: '10000000146', firstname: 'Ahmet', lastname: 'Yılmaz', birthyear: 1990 },
    { tcno: '99000000042', firstname: 'John', lastname: 'Doe', birthyear: 1985 },
  ],
  { batchSize: 50 } // istek başına kriter sayısı (varsayılan 50)
);
```
- Tek STS token'ı kullanılıyor ve her `batchSize` kriter için tek KPS isteği gönderiliyor.
- Hiçbir istek gönderilmeden önce tüm girdiler doğrulanıyor. Hatalı kayıtların sırası `error.details.errors[].index` içinde.
- Sonuçlar girdi sırasıyla dönüyor.
- KPS her kriteri ayrı sorgu olarak ücretlendirir. Toplu gönderim ücretten değil, ağ gidiş-dönüşünden tasarruf sağlar.

### TC Kimlik Kartı seri numarası
```typescript
await client.verify({ tcno: '10000000146', firstname: 'Ahmet', lastname: 'Yılmaz', birthyear: 1990, serialno: 'A12B34567' });
```

### TC Kimlik No algoritma kontrolü
```typescript
import { isValidTCKimlikNo } from '@yucelozalp/kps-identity-client';
isValidTCKimlikNo('10000000146'); // true

new KPSClient({ username, password, validateChecksum: true }); // hatalı numaralar KPS'e gitmeden reddedilir
```
Her KPS sorgusu ücretli olduğu için yanlış yazılmış numaraları yerelde elemek maliyeti düşürür.

### Daha zengin sonuçlar ve hatalar
- `result.extra.Ulke`: Mavi Kart sahiplerinin ülkesi.
- `result.hataBilgisi`: KPS'in o kayıt için döndürdüğü hata (`{ kod, aciklama }`).
- İstek seviyesindeki KPS hataları (ör. yetki) `ServiceError` fırlatır; ayrıntı `error.details.hataBilgisi` içindedir.
- `ServiceError` / `STSError` → `error.details.fault` (`code`, `subcode`, `reason`).
- `NetworkError` → `error.details.code` (ör. `ECONNREFUSED`, `ETIMEDOUT`). IP kısıtı sorunlarını teşhis etmeyi kolaylaştırır.

### Yeni yapılandırma seçenekleri
| Seçenek | Varsayılan | Açıklama |
|---|---|---|
| `cacheToken` | `true` | STS token'ını süresi dolmadan 1 dk öncesine kadar yeniden kullan |
| `validateChecksum` | `false` | TC Kimlik No algoritmasına uymayan numaraları yerelde reddet |
| `includeRaw` | `true` | Sonuçlara ham SOAP yanıtını ekle (KVKK için `false` önerilir) |
| `logger` | `console` | Debug çıktısı için `{ debug(...) }` arayüzü |
| `endpoints` | resmi adresler | `{ sts, query }`: reverse proxy veya test sunucusu adresleri |
| `httpConfig.keepAlive` | Node varsayılanı | TLS bağlantılarını yeniden kullan |
| `httpConfig.httpsAgent` | — | Proxy agent veya özel TLS ayarları |

Ayrıca `clearTokenCache()` metodu eklendi ve doğum alanları artık sayı da kabul ediyor.

## Performans

Yerel sahte KPS sunucusunda, istek başına 50 ms gecikme ile 20 kişinin doğrulanması:

| Yöntem | Toplam süre | HTTP isteği |
|---|---|---|
| 1.0.x akışı (token önbelleği yok), sıralı | 2126 ms | 40 |
| 1.1.0 `verify()`, sıralı | 1126 ms | 21 |
| 1.1.0 `verify()`, `Promise.all` | 127 ms | 21 |
| 1.1.0 `verifyMany()` | 109 ms | 2 |

- Token, STS'in bildirdiği ömrün bitmesine 1 dakika kalana kadar kullanılıyor. Ömür `Expires - Created` farkından hesaplandığı için yerel saat sapması önbelleği etkilemiyor.
- Aynı istemcideki eşzamanlı çağrılar tek bir STS isteğini paylaşıyor.
- KPS önbellekteki bir token'ı reddederse istemci yeni token alıp sorguyu **bir kez** tekrarlıyor. KPS güvenlik kontrolünü sorguyu çalıştırmadan önce yaptığı için bu tekrar mükerrer ücretlendirmeye yol açmaz.

> Önbellekten yararlanmak için `KPSClient`'ı bir kez oluşturup yeniden kullanın. Her istekte yeni istemci oluşturmak önbelleği devre dışı bırakır.

## Güvenlik

- Debug logları artık `logger.debug` üzerinden yazılıyor. **Parola** ve **STS proof key** (`BinarySecret`) `***` ile maskeleniyor. 1.0.x'te ikisi de açık metin olarak yazılıyordu.
- Bağımlılıklar güncellendi: `npm audit` 0 açık gösteriyor (önceden 1 kritik, 8 yüksek, 5 orta ve 1 düşük seviyede toplam 15 açık vardı).
- `uuid` bağımlılığı kaldırıldı, yerine Node.js'in `crypto.randomUUID()` fonksiyonu kullanılıyor. Çalışma zamanı bağımlılığı artık sadece `axios` ve `xml2js`.

## Yükseltme notları

API geriye dönük uyumlu, mevcut kodunuz değişiklik yapmadan çalışır. Yine de şu davranış değişikliklerine dikkat edin:

1. **Gerçek sonuçlar dönüyor.** 1.0.x'te imza hatası ya da `status: false` alan sorgular artık KPS'in gerçek cevabını döndürecek.
2. **`birthday` tek başına verilemez.** Doğum günü verilen isteklerde `birthmonth` da zorunlu; yoksa `ValidationError` fırlatılır. Bu kombinasyon KPS'te zaten anlamlı bir sorgu üretmiyordu.
3. **İstek seviyesindeki KPS hataları exception olarak geliyor.** `SorgulaResult.HataBilgisi` dolu dönerse `ServiceError` fırlatılır. Kayıt bulunamaması hata değildir; `status: false` döner.
4. **Token önbelleği varsayılan olarak açık.** Eski davranış için `cacheToken: false` kullanın.
5. **Debug çıktısı `console.debug`'a gidiyor** (önceden `console.log`). Farklı bir hedef için `logger` verin.
